**`nook run` no longer waits when a secret needs the owner's approval. It returns the approval link at once.** An agent reads a command's output only when the command ends, so the link printed by a waiting run reached the owner late or never. Now a run that needs approval starts nothing, exits 75 and prints the link, the time left and an attempt id:

```
work/acme/STRIPE_KEY needs the owner's approval. Nothing ran yet.
Tell the owner now to open https://nook.example.com/approvals/3f2c…
Then run the same command again with --approval 6a1e… after "nook run". That run waits for the owner's decision (10:00 left).
```

Give the owner the link, then run the same command with `--approval <id>`. That run waits for the decision, up to 10 minutes from the first run, and starts the command when the owner approves. It must match the first run: same purpose, directory and secrets.

A run covered by a remembered approval (1 hour or 12 hours) is delivered at once and needs no `--approval`. *Only this time* still lasts 2 minutes after the decision, so resume right after you give the owner the link.

When a request expires, is withdrawn, or its secrets change, the message now ends with `Run again without --approval to ask again.` The exit codes are unchanged: 75 for these cases and 77 for a denial.
