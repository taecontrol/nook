# Verification

Run `pnpm verify` from the repository root with the pinned Node and pnpm versions. It stops on the first failure, in this order:

| Command | What it proves |
| --- | --- |
| `pnpm verify:style` | Biome formatting, recommended lint rules, and import order. |
| `pnpm verify:ui` | The web app composes shadcn/ui with theme tokens, static known classes, and the approved component composition rules. |
| `pnpm verify:types` | TypeScript checks the app, contract, tooling, and tests. |
| `pnpm verify:complexity` | Classic cyclomatic complexity is at most eight for each authored function. |
| `pnpm verify:migrations` | D1 migrations replay on an empty, already-migrated, and populated previous schema; drift, edited published migrations, and explicit transactions fail. |
| `pnpm test:coverage` | Vitest tests Node policies, the built Worker under workerd, the CLI as real Node processes with private Secret Service, and the web app in Chromium; then `e2e run --strict-cache` runs the deterministic owner journey with zero retries. |
| `pnpm verify:crap` | Complete, current execution evidence gives each scoped function a CRAP score at most eight. |
| `pnpm build` | Vite builds the SPA and esbuild bundles the Worker for workerd and the CLI for Node 26. |
| `pnpm verify:load-time` | The production first screens and navigation fit fixed load-time budgets on a 4G phone network. |

`pnpm test` builds the production target before running Vitest. A narrow run such as `pnpm test tests/worker.test.ts` uses the same HTTP target. After `pnpm test`, `pnpm test:journey` runs the journey against that target, with the same allowlisted environment and host-resource tripwire; strict cache replay and zero retries stay mandatory. `pnpm test:coverage` prepares its own separately instrumented build and needs no prior build. The complete test, coverage, verification, and load-time commands also keep their build, E2E, and browser subprocesses inside the isolation lifecycle.

All local identities, signing keys, and issuer responses are synthetic. CLI tests require Node 26.10, `dbus-run-session`, `dbus-send`, `gnome-keyring-daemon`, and `secret-tool`. CI installs `gnome-keyring`, `libsecret-tools`, and `dbus` in the test jobs. Each CLI fixture creates private HOME/XDG directories, including XDG_DATA_HOME for the encrypted keyring files, and a private bus with no service activation directories, asserts that its address differs from the inherited bus, and unlocks a real isolated keyring before launching the CLI. The daemon runs with `--foreground` alongside `--unlock --components=secrets`: the fixture waits for stdout EOF after initialization, then requires a real store/lookup/clear probe. The background launcher exits before initialization, so its exit is insufficient. Daemon streams are discarded. PATH shims record opener URLs and secret-tool argv, then delegate to the real binaries; the bus-identity shim delegates to the real dbus-send; values travel only over stdin. Missing-service tests deliberately omit the daemon. Fixtures reject bus overrides before every child, clean failed setup, stop the owned daemon and children before removing HOME, and kill any remaining private process group; shutdown has a bounded force-kill fallback. A concurrent fixture regression proves that inherited XDG data remains untouched. The runtime reads asset routing and compatibility settings from `wrangler.jsonc`, binds only to `127.0.0.1`, and takes explicit test bindings. Test port leases stay above Fetch's blocked-port range and outside Linux's ephemeral range. No test reads production credentials or contacts a Cloudflare account. Coverage endpoints and counters exist only in the test build.

`pnpm test tests/mcp-worker.test.ts tests/mcp-handlers.test.ts tests/mcp-transport.test.ts tests/mcp-web.test.ts` proves the remote bucket tools, grant denial, authentication and Origin ordering, sanitized errors, and both observed client protocol revisions. The fetch driver follows Claude Code 2.1.289's 2026-07-28 discovery and Codex 0.160.0's 2025-06-18 initialization, reading JSON and SSE. The Codex transport test restarts workerd between every step and also calls a tool as the first request of an isolate.

The MCP browser test launches the installed Chromium with its own temporary profile and loopback debugging port, then connects Playwright with `noDefaults`. This preserves native tab visibility, which Playwright's default focus emulation otherwise overrides. It verifies an external MCP creation while the real tab is hidden, then exactly one list request and a nested bucket on return, for both fresh and stale cached data. The fixture closes Chromium and removes its profile. The same test runs locally and in CI without a display server or extra dependency.

Vitest's global host-resource tripwire runs for `pnpm test`, `pnpm test:coverage`, and `pnpm verify`, including CI shards. It resolves the real owner with `os.userInfo().homedir`, fingerprints entry names and kinds beneath the owner's keyring directories, and preserves an explicit absent state. Existing keyring file sizes and mtimes are not compared: legitimate owner applications refresh stored credentials while verification runs. A Codex OAuth refresh was attributed to such a change during diagnosis. Added or removed entries, changed kinds, and a directory appearing or disappearing still fail. The Nook configuration directory also compares sizes and mtimes. Teardown names the changed resource and entries without exposing contents, detects leftover processes with temporary CLI HOME or a run-owned keyring/bus daemon, kills those processes after checking PID identity, and reports them; it never cleans owner resources.

The observer does not contact D-Bus, including private buses, and has no Secret Service fingerprint. In Ubuntu's systemd 255, `busctl get-property` ignored `--auto-start=no` and activated gnome-keyring, creating the owner keyring directory on a fresh runner. Replacing it with a non-activating `Properties.Get` call was also unsafe: during verification on 2026-10-05 at 10:01:34, the owner's gnome-keyring daemon aborted with SIGABRT in its property handler after a client disconnected, consistent with the observer's short timeout. Even read-only calls can harm the service. The filesystem observer cannot detect changes to items inside an existing keyring file; prevention comes from the allowlisted child environments, explicitly unavailable default bus, and private-bus fixtures. Kernel-enforced isolation remains the guarantee tracked in [#35](https://github.com/taecontrol/nook/issues/35).

The test runner and every host-touching child use environments built from an explicit allowlist, with temporary HOME and all XDG directories. Parent bus, keyring, credential, display, and arbitrary environment variables do not propagate. An explicit unavailable bus address prevents implicit discovery of the owner's bus; private-keyring fixtures replace it with their own bus. The owner's HOME is rejected as a temporary HOME. `NODE_OPTIONS` is accepted only as an explicit fixture injection; coverage output paths are supplied explicitly. Directory overrides must stay inside temporary HOME, except the documented CLI config fallback. Chromium gets a fresh temporary profile, `--password-store=basic`, `--use-mock-keychain`, and no owner bus. The E2E engine runs under the same isolated caller environment and uses Playwright's basic/mock defaults. Regression tests inspect the real CLI, daemon and browser launch environments, deliberately mutate a fake owner tree to prove the tripwire fails while same-name keyring metadata refreshes do not, prove filesystem observation cannot activate a reachable synthetic service, and terminate a synthetic orphan.

## Coverage and CRAP

The coverage inventory starts from original TypeScript and TSX, including files no test imports. [coverage.config.json](../../coverage.config.json) defines the scope: CLI, Worker, web, contract, and the Node policy modules in `scripts/lib`. Script entry points are orchestration and are covered by command and workflow acceptance checks; every authored script function still enters the complexity check. Unconfigured executable extensions fail inventory validation.

Unchanged CLI-generated shadcn components and their mobile hook are recorded by SHA-256 in [generated-components.json](generated-components.json). Changing one fails the inventory until it enters authored scope. The generated primitives retain their standard internal styles; authored composition still obeys all six UI rules. Declarations and dependencies do not enter authored coverage.

Istanbul instruments original sources before Node execution, CLI child-process bundling, Worker bundling, and browser compilation. The CLI test entry records its counters at process exit without recording arguments, environment values, or command output. The CLI execution seam is required whenever CLI sources enter the inventory. Coverage artifacts in `.local/verification/coverage/` include a zero baseline, each seam's loaded-module hashes and counters, and a manifest of artifact hashes. Source identity includes app, contract, tooling, tests, documentation, workflows, configuration, and the lockfile, using repository-relative paths so a clean export and a CI shard agree.

CRAP rejects a missing baseline or seam, empty or unexecuted seam observations, stale source, unknown modules, incompatible counter maps or shapes, and altered artifacts. Coverage is the fraction of the function's own statements executed, excluding nested functions. A statement-free function uses its function counter. Classic complexity counts decisions independently for each function. The score is `complexity² × (1 − coverage)³ + complexity`.

CI runs the five static commands, three `pnpm test:coverage --shard=I/3` jobs, and a final job. Each shard uploads its manifest and artifacts; the final job requires the distinct indexes `1/3`, `2/3`, and `3/3`, identical source identities and baselines, and intact artifact hashes before CRAP, build, and the load-time check. The timing stage runs alone after test jobs finish. It needs no Cloudflare secrets.

## Browser evidence and budget

The shell suite captures all five accepted states at 1440×900 and 390×844 in both light and dark. It checks horizontal overflow, card bounds, rendered email line breaks after allowed separators, disabled future tools, mobile Sheet behavior, and the full-email dropdown with the Access logout destination. The twenty base screenshots and six overlay screenshots appear in `.local/verification/screenshots/` and CI's `web-shell-I` artifact. Compare them with the chosen prototype when changing the shell.

The owner journey uses a recorded `agent.act` to create `work/acme`, followed by an exact locator proving nesting inside `work`. Local recording uses the owner's ChatGPT subscription through `e2e/oauth/chatgpt`; credentials are never copied. Committed `.e2e/cache/` recordings replay in CI with `e2e run --strict-cache` and zero retries or model calls. Reports, logs, videos, and failure artifacts stay ignored and are uploaded on CI failure.

The bucket suite captures nine states at both viewport sizes, in light and dark: typical, fresh, deep-and-long, loading, load-error, ancestor preview, invalid path, delete confirmation, and after creating `work/acme`. The `buckets-*` PNGs share the screenshot artifact with shell evidence. Scenario controls and stubs are test fixtures and never enter the product.

The load-time stage uses Chromium against the uninstrumented production build and the same local runtime with the synthetic owner. It emulates 9 Mbps down, 3 Mbps up, and 85 ms latency, with cache disabled and no CPU throttling. Each result is the median of five runs. A cold `/cli/authorize` must show the terminal-code field within 1000 ms. A cold `/` must show the signed-in owner's email within 1000 ms; a cold `/buckets` must show outline rows within 1000 ms. From home, after hovering Buckets until intent preloading settles, navigation must show rows within 100 ms. Constants live in `scripts/lib/load-time.ts`. Browser marks measure rendered screens across animation frames, excluding automation round trips. Medians, individual samples, and cold-open gzip bytes are printed; bytes are diagnostics and never gate.

The CLI approval suite captures twelve states at 1440×900 and 390×844 in light, plus pending, approved, and expired in dark. Thirty `cli-authorize-*` PNGs and a mobile brand-focus capture share `.local/verification/screenshots/` and CI screenshot artifacts. The chosen Enter-the-code prototype is the fidelity reference. Checking stays on step one as recommended by the judge; the brand focus ring remains within the mobile viewport and long names wrap below the input. Focus captures disable animations so the ring has settled. `tests/cli-*.test.ts` proves accepted CLI login examples; production Access and Omarchy captures (E25) remain the owner’s post-deployment step in [deployment.md](../deployment.md).

Session concurrency tests run overlapping real login/logout processes against one private keyring, including different config directories and a held keyring deletion. A Linux abstract socket coordinates credential-changing commands for the same user and actual Secret Service bus ID, obtained by the real `dbus-send`; it carries no credential and disappears on process exit. Private-bus aliases omit guid, escape the path, use a symlink, or add a failed fallback address; each proves the same bus ID before running the CLI. SIGKILL and denied-login tests prove subsequent commands can proceed. D1 failure tests use real aborting SQL triggers to prove rollback and retry of creation, approval, exchange, and revocation. Request-time assertions bracket the creation call so a shifted ten-minute deadline cannot pass by preserving only the difference between stored timestamps. Approval retries prove that retrying Deny never grants access, including with an empty machine name.

The race suite decorates the genuine D1 binding used by the built Worker, pausing after reads or before and after atomic batches. It forces overlapping decisions, one-time exchanges, and immutable deadlines passing during delayed writes. Checkpoint observers receive fixed labels only, never SQL, bindings, rows, or credentials. Expiry predicates evaluate the database clock when the write executes. Failure and recovery tests keep command and HTTP diagnostics private even when a credential-leak regression fails.

## Migrations

`migrations/NNNN_name.sql` files are applied in order using Wrangler's SQL splitter and one atomic D1 batch per file, including its `d1_migrations` record. `migrations/schema.sql` is a snapshot, not a migration. The D1 binding's `migrations_pattern` selects only numbered files; a local Wrangler acceptance test proves that it excludes the snapshot and preserves replay. Verification uses fresh Miniflare databases, checks an idempotent replay, and applies the latest file to the previous schema containing a sentinel bucket. Both final normalized schemas must match the snapshot, and the sentinel must remain unchanged. A second migration enforces the reserved `me` invariant at the database boundary.

Fetch `origin/main` before verification: a migration present there cannot change or disappear. SQL errors, schema drift, and `BEGIN TRANSACTION` fail the gate. Deployment relies on the commit's successful Verify run instead of repeating it, builds, creates the named database if missing, applies remote migrations, then deploys the Worker. Production acceptance remains an owner step described in [deployment.md](../deployment.md).
